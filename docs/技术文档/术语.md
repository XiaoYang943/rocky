# Rocky 技术文档术语

## 使用约定与来源

本页是本目录的术语权威入口，提供英文原名、中文释义、源码标识及容易混淆的边界。其他技术正文优先使用英文术语，保留中文说明句；中文释义用于理解，不代替 API、数据结构或算法的英文名称。

源码基线为 Rocky `a4d8b141ec478e8440526928b344c6eb93810631`。下文区分三种名称：`Profile`、`TileKey` 等是代码标识，大小写与源码一致；Tiling、Paging、Culling 等是机制名称，不意味着存在同名 C++ 类；EPSG、MVT、3D Tiles 等属于外部规范或格式。G 编号对应文末的本地源码入口，本页不新增功能支持或实测结论。

基础库调研补充使用 F 编号，分别对应 VSG、vsgXchange 和 OSG 的固定来源；osgEarth 仅作官方文档概览。版本与阅读边界见[调研来源](调研分析/来源与版本.md)，不能将下面的 VSG 定义当作 OSG 或 Rocky 中同名对象的完整契约。

具体规则：

1. 正文直接写 `Profile`、Tile、Paging 等原名，需要解释时链接本页；不反复给同一术语创造不同中文译法。
2. 类、函数、字段、JSON 键和宏按源码原样书写，例如 `profile`、`invert_y`、`invertY`。术语统一不更改代码标识。
3. 按上下文选择英文：可见性排除用 Culling，影像范围限制用 Crop，几何边界截取用 Clipping；不能把三者统一成同一个词。
4. 栅格、矢量、影像、高程、三维地形等业务分类，以及普通中文解释继续使用中文。目录、文件名、既有用户原话及上游原文保留原样；历史检查记录保留当时事实，当前用词以本页为准。
5. 新遇到术语时先查源码定义、注释和调用点，再补充本表；没有对应类时明确写为概念，不虚构 API。

## 框架与应用对象

| 英文原名／代码标识 | 中文释义 | 在本库中的含义与边界 |
| --- | --- | --- |
| OpenSceneGraph / OSG | 基于 OpenGL 的场景图框架 | 理解背景，不是 Rocky 的运行基础。 |
| osgEarth | 基于 OSG 的地理空间 SDK | 与 Rocky 有相近的问题域，不表示对象或接口兼容。 |
| VulkanSceneGraph / VSG | 基于 Vulkan 的场景图框架 | Rocky 使用的底层框架；GIS 数据读取不由 Vulkan 本身提供。（G1） |
| Application | 应用默认装配 | `Application` 组织 Viewer、地图、窗口、ECS 及 Frame Loop；自定义宿主可以自行装配。（G1） |
| Viewer | 渲染任务与窗口的运行管理对象 | VSG Viewer 负责事件、更新、命令提交等；不能等同于单个 UI 控件。（G1） |
| View | 相机对应的场景观察配置 | 可关联 Camera、场景和 Viewport；不等于原始数据的 SRS。（G1） |
| Camera | 相机 | 决定场景观察方向及投影；与输入文件的空间参考或 Image 数据解释方式不同。（G1） |
| Viewport | 图像输出区域 | 窗口中的绘制区域；与 GIS 数据的 GeoExtent 不同。（G1） |
| Context / IOOptions | 通用上下文／一次读取的环境选项 | 提供服务、读取环境和取消状态；不同于 Vulkan Device 本身。（G2） |
| VSGContext | 渲染上下文服务入口 | 本版为 `VSGContextImpl*`；实际所有者须存活，不能把复制指针当作取得所有权。（G2） |
| Map / MapNode | 地图数据模型／地图场景节点 | `Map` 保存 Layer；`MapNode` 才连接 VSG Scene Graph。（G1、G3） |
| Layer / VisibleLayer / NodeLayer | 图层／带外观状态的图层／节点图层 | `Layer` 是数据与生命周期单元；`NodeLayer` 承载已有 VSG Node，不自动解析任意模型格式。（G3） |

## Tile、Profile 与请求组织

| 英文原名／代码标识 | 中文释义 | 在本库中的含义与边界 |
| --- | --- | --- |
| Tile | 瓦片 | 某个 Level 下的一块数据区域；必须结合 Profile 才能解释 z/x/y 的空间位置。（G4） |
| Tiling | 按空间布局组织 Tile 的过程或机制 | 不使用“铺瓦”作为正文术语；它容易模糊布局、生产切片与运行时请求之间的区别。Tiling 是概念，不是 `Profile` 的别名类。（G4） |
| Profile / Tiling Profile | 空间参考及 Tile 布局定义 | `Profile` 包括 SRS、Extent、Root Level 的列数/行数和可选 Subprofile；不是单一 EPSG 代码，也不是用户配置档案。（G4） |
| Tile Grid / Root Layout | 瓦片空间网格／根层布局 | 描述 Tile 的空间划分，不表示送入 GPU 的 Mesh；Root Layout 影响相同 z/x/y 的实际范围。（G4） |
| Source Profile / Request Profile | 数据源布局／请求布局 | 驱动的数据布局和请求 TileKey 的布局可以不同；`assembleTile` 负责相关转换与 Mosaicing。（G5） |
| Subprofile / Composite Profile | 子布局／组合布局 | `Profile::subprofiles()` 与 `isComposite()`；例如一个布局可由多个子布局组成。（G4） |
| TileKey | 带布局信息的 Tile 地址 | 包含 Level、x、y、Profile；内部 y 从上向下增加。（G4） |
| Level / LOD（Level of Detail） | 层级／细节层级 | Level 常指索引层级；LOD 还涉及细节选择，不能等同于压缩率或真实测量精度。（G4、G8） |
| Root / Parent / Child / Ancestor Tile | 根／父／子／祖先瓦片 | 是层级关系，不是文件目录关系；Parent TileKey 的 x/y 各减半取整。（G4） |
| Tile Pyramid | 多层级瓦片金字塔 | 预生成 Tile 与原始文件按需产生 Tile 都可参与层级显示；不能据此推断已经生成磁盘文件。 |
| XYZ / TMS | 常见 Tile 寻址约定／Tile Map Service | 行号方向还受具体服务、Profile 与驱动设置影响；不要只看扩展名。（G6） |
| Extent / GeoExtent | 范围／带 SRS 的二维地理范围 | `GeoExtent` 不是 ECEF 三维 Bounding Box；转换到地心目标时实际转到其地理 SRS。（G7） |
| DataExtent | 带 Level 信息的数据覆盖范围 | 为 `bestAvailableTileKey` 提供覆盖提示；不是每个文件都存在的证明。（G5） |
| minLevel / maxLevel / maxDataLevel | 最小参与层级／最大参与层级／有效数据层级提示 | `maxLevel` 与 `maxDataLevel` 不能混用；具体默认值与驱动行为以代码为准。（G5） |
| tileSize | 数据或网格每边的采样数 | 必须指明所属对象：TileLayer、ElevationLayer、TerrainSettings 的含义和默认值不同。（G5、G8） |
| Paging / Pager | 按需调入、保留与卸载数据／执行该机制的对象 | 不使用 UI 翻页的含义。`TerrainTilePager` 管理地形，`NodePager` 可承载按 TileKey 构建的普通 Node。（G8、G9） |
| Refinement / RefinePolicy | 选择更细内容／细节替换策略 | NodePager 的 `RefinePolicy::Replace` 与 `Accumulate` 是实际标识；不等同于生成新顶点的 Subdivision。（G9） |
| Fallback / Parent Fallback | 请求失败或细节不足时的替代／父级替代 | 源 Tile 的祖先回退与场景沿用 Parent 数据是不同阶段，不保证每次请求都有有效输出。（G5、G8） |
| Residency / Resident | 数据处于驻留状态／已驻留的 | 需指明是在 Node、CPU 数据还是 GPU 资源管理层；不等于永久存储。（G8、G9） |
| Cache / Resident Cache / Cache Key | 缓存／驻留缓存／缓存键 | Tile 缓存包含 TileKey、Layer UID、Revision 与 source 标志；不存在自动启用所有缓存的保证。（G5） |
| UID / Revision | 运行时对象标识／内容修订计数 | UID 不默认跨进程稳定；`dirty()` 改变 Revision，不等于同步重建全部地形。（G3、G5） |

## 空间参考与精度

| 英文原名／代码标识 | 中文释义 | 在本库中的含义与边界 |
| --- | --- | --- |
| SRS / CRS | 空间参考系统／坐标参考系统 | Rocky 类型名是 `SRS`，PROJ 接口使用 CRS 概念；EPSG 标识只是定义方式之一。（G7） |
| SRSOperation / Coordinate Operation | 空间参考之间的坐标操作 | `from.to(to)` 建立变换；不等同于重新给数值贴一个 SRS 标签。（G7） |
| Axis Order | 坐标轴顺序 | 常用 GIS 输入为 longitude=x、latitude=y；要核对 PROJ normalization，而非机械交换 x/y。（G7） |
| Coordinate Units | 坐标单位 | 度、弧度与米必须明确；当前 `SRS::units()` 不是任意 CRS 的完整单位查询。（G7） |
| Geodetic Coordinates | 大地／地理坐标 | 常用经度、纬度、椭球高；本库 `SRS::WGS84` 别名对应 EPSG:4979。（G7） |
| Projected Coordinates / Projection | 投影坐标／投影 | 平面表达和投影操作；输入使用投影坐标不意味着最终只能显示平面地图。（G7） |
| Geocentric Coordinates / ECEF | 地心坐标／地固地心坐标 | Earth-Centered, Earth-Fixed；本库 WGS84 地心参考为 EPSG:4978。（G7） |
| ENU / Local Frame | 东北天坐标／局部坐标框架 | East-North-Up；以某处为原点的局部框架，需要匹配其位置和轴向。（G7） |
| QSC（Quadrilateralized Spherical Cube） | 将球面映射到立方体六面的投影 | Rocky 的 `global-qsc` 由 Subprofile 组成；名称与投影含义参见 [PROJ QSC 文档](https://proj.org/en/stable/operations/projections/qsc.html)，本库布局见 G4。 |
| World Coordinates / Local Coordinates | 世界坐标／对象局部坐标 | MapNode 的 World SRS 随 Profile 而定；Local Coordinates 需要相应 Transform。（G1、G7） |
| Localization / origin | 数值局部化／局部参考原点 | 减小 Geometry 数值量级；FeatureBuilder 的 origin 需要配套恢复位置的 Transform。（G10） |
| Vertical Datum / Compound CRS | 垂直基准／复合坐标参考系统 | 不可把任意灰度值都解释为米；转换可能依赖 PROJ 数据库与 Grid。（G7） |
| Antimeridian | 反经线 | 跨 ±180° 的范围与 Geometry 需保留跨线语义，不是交换两个经度就能处理。（G7、G10） |
| PROJ Grid | 坐标转换使用的格网数据 | 可能参与水平或垂直基准转换；与 Tile Grid 的索引布局不同，缺失时需检查实际 Coordinate Operation。（G7） |
| Position Precision / Depth Precision | 位置精度／深度精度 | 局部化与 double 主要处理位置数值；Depth Buffer 的遮挡精度是另一问题。（G7、G11） |

## 栅格与高程处理

| 英文原名／代码标识 | 中文释义 | 在本库中的含义与边界 |
| --- | --- | --- |
| Image / GeoImage | 图像容器／带地理范围的图像 | GeoImage 同时保存 Image 与 GeoExtent；Image 不一定是显示颜色，也可能承载高度。（G5） |
| Pixel Format / Image::viewAs | 像素格式／按另一格式共享读取数据 | `Image::viewAs` 共享原像素数据，不执行数据转换；不是 Camera View 或 Vulkan ImageView。RGB 高程路径借此避免 sRGB 转换。（G8） |
| Raster Band / Color Interpretation | 栅格波段／颜色解释 | GDAL 驱动据此寻找 RGB、Alpha、Gray、Palette 等通道；不等同于任意波段制图。（G6） |
| GeoTransform（GDAL） | 像素与地理位置之间的仿射参数 | 用于地理范围与像素窗口转换；与场景中的 `rocky::GeoTransform` 类不同。（G6、G7） |
| RasterIO / Source Window | 栅格窗口读取／源像素窗口 | GDAL 按窗口读取和重采样；不保证已生成 Overview。（G6） |
| Sampling / Resampling | 取样／重采样 | 改变采样位置或密度，不增加原始数据真实精度。（G5、G6） |
| Interpolation / Nearest / Bilinear | 插值／最近邻／双线性 | 需区分字段默认值及实际路径，不把颜色插值直接套用到编码高度。（G6、G8） |
| Reprojection | 重投影 | 涉及空间映射与采样；不等同于仅修改 SRS 标签。（G5、G6） |
| Mosaicing / assembleTile | 多源 Tile 拼接／构建请求布局的 Tile | 根据交叠源 Tile 采样成目标结果；与多 Layer 的颜色叠加不同。（G5） |
| Color Compositing / opacity | 颜色合成／透明度参数 | `GeoImage::composite` 结合 Layer 顺序和 opacity；不等同于源文件写回。（G5、G8） |
| Crop / crop | 影像或请求的地理范围限制 | 对应 TileLayer 的 crop 和 ImageLayer 请求处理；与 Culling、Clipping 分开。（G5） |
| NoData / NO_DATA_VALUE | 无有效数据／内部无效高度值 | 不是零高程；RGB 解码、浮点高度和 R16 码值需按各自规则识别。（G8） |
| Overview / COG / VRT | 概览／云优化 GeoTIFF／虚拟栅格 | 属于文件组织或 GDAL 路线；接口存在不证明本机驱动或性能已经验证。（G6） |
| DEM / Heightfield | 数字高程模型／规则采样的高度场 | DEM 是数据模型；`Heightfield` 是 Rocky 高度访问与编码工具。单值高度场不能表达任意悬垂表面。（G8） |
| Terrain-RGB / Terrarium | 两种将高度编码进颜色通道的约定 | 需按对应公式解码；不能当普通 sRGB 颜色参与处理。（G8） |
| R32_SFLOAT / R16_UNORM | 单通道浮点／单通道 16 位归一化格式 | 本路径先在 CPU 得到浮点高度，再编码为 R16 并携带 min/max；R16 码值不直接等于米。（G8） |
| Elevation Sampling / Clamping | 查询源高程／把 Geometry 放到地表高度 | FeatureBuilder clamper 可用 ElevationSession；与当前场景 Mesh 的 Intersection 不同。（G8、G10） |

## Scene Graph、Geometry 与 GPU

| 英文原名／代码标识 | 中文释义 | 在本库中的含义与边界 |
| --- | --- | --- |
| Scene Graph / Node / Group | 场景图／节点／分组节点 | 描述可遍历对象关系；Geometry 可以共享，不必是严格树。（G1、G11） |
| Transform / rocky::GeoTransform | 坐标变换节点或组件／地理定位节点 | 将 Local Coordinates 放入场景；后者不是 GDAL 仿射参数。（G7、G10） |
| Geometry / Mesh / Vertex / Vertex Array / Index | 几何数据／网格／顶点／顶点数组／索引 | 数据表示与拓扑；准备好数组不等于已经创建可绘制 ECS Entity。（G10、G11） |
| Bounding Volume / Bounding Sphere / Bounding Box | 包围体／包围球／包围盒 | 用于可见性、LOD、查询等保守判断；GeoExtent 是不同对象。（G8、G11） |
| Culling / View Frustum / Horizon Culling | 可见性剔除／视锥／地平线剔除 | 排除无需绘制的对象，不是改变源像素或切割几何边界。（G1、G11） |
| Clipping | 按边界截取几何或图元 | 例如 MVT 的 `CLIP=NO` 是数据读取选项；与 View Frustum Culling 不同。（G9） |
| Visibility / ActiveState | 可见性／活动状态 | ECS 组件各有职责；NodeLayer 生命周期与逐帧/逐 View 可见性不能混同。（G3、G10） |
| Subdivision | 将线段、面或空间区域进一步划分 | 线段沿球面的采样和 Tile 产生子级都可能使用此概念；应说明处理对象。（G8、G10） |
| Triangulation / Tessellation | 转成三角形／分解为可绘制单元 | Tessellation 的范围依算法而定；本库有 CPU 面处理，不能据名称推断启用 Vulkan GPU Tessellation。（G10、G11） |
| Skirt | 网格边缘向下延伸的遮缝几何 | `skirtRatio` 控制比例；不能提高源高程精度，也不等同于 Morphing。（G11） |
| Morphing / Geomorphing | Geometry 在细节状态之间渐变 | 存在 morphing 参数不表示默认启用；当前工厂路径传入 false。（G11） |
| Proxy Geometry | 用于边界或查询的代理几何 | CPU 根据高度维护的代理与最终 GPU 位移后的画面需分别判断。（G11） |
| Texture / Buffer / Shader | 纹理／数据缓冲／着色程序 | 是 GPU 渲染资源与程序，不是 TIFF/OBJ 文件本身。（G2、G11） |
| Uniform / Descriptor / Graphics Pipeline | 着色输入／资源描述／图形管线 | TerrainState 与 Shader 通过绑定使用资源；不把它们笼统称为同一种渲染状态。（G11） |
| Depth Buffer / Depth Offset | 深度缓冲／深度偏移 | 处理遮挡关系或共面冲突；Depth Offset 不代替 Clamping。（G10、G11） |
| Frame Loop / RecordTraversal | 帧循环／命令记录遍历 | 事件、更新、记录、提交、显示有不同阶段；后台读取不等于已完成 GPU 绘制。（G1、G2） |
| Compile（VSG resource compile） | 为渲染准备或创建资源 | 区别于 C++ 编译器构建；`VSGContext::compile` 属于运行时资源准备。（G2、G8） |
| Upload / Merge / Update | 传输资源／合并结果／更新阶段 | 应明确主语和阶段；后台数据在适当 Update 阶段进入场景，不能随意跨线程改场景。（G2、G8） |
| Intersection / Picking | 与场景几何求交／选取对象 | 当前 Terrain Intersection、源高程 Sampling、实体 Picking 不是同一个查询。（G8、G10） |

## Feature、ECS 与数据访问

| 英文原名／代码标识 | 中文释义 | 在本库中的含义与边界 |
| --- | --- | --- |
| GDAL / OGR / Driver | 数据访问库／矢量接口体系／格式驱动 | Rocky 接口存在不等于所用 GDAL 构建含全部 Driver。（G6、G12） |
| Dataset / Subdataset / Metadata | 数据集／子数据集／元数据 | 需区分实际数据、所选子集和描述信息；GDAL 的数据组织不等于已经创建可绘制 Node。（G6、G12） |
| Feature / FeatureSource | 要素／要素来源 | Feature 包含 Geometry、SRS、字段与 ID；GDALFeatureSource 读取 Feature，不继承 Layer。（G12） |
| Polygon / Exterior Ring / Hole / Multipart | 多边形／外环／内洞／多部件 | 源数据结构与渲染结果分别验证；支持读取环不等于任意无效 Geometry 都会被修复。（G10、G12） |
| FeatureBuilder | 构建 Geometry 的工具 | 公开 build 方法不等于完整 style.json 引擎，也不自动提供编辑保存。（G10） |
| ECS / Entity / Component / System | 实体组件系统／实体／组件／系统 | Entity 是标识，Component 存数据，System 处理组件；Rocky 通过 Registry 与 Scene Graph 协作。（G10） |
| Primitive Component / Style / Overlay | 图形组件／样式／覆盖绘制 | Point/Line/Mesh/Polygon 组件引用对应 Geometry/Style；Overlay 是另一个绘制机制，不是普通高度采样。（G9、G10） |
| Payload | 按请求构建的有效内容或承载结果 | `NodePager::Payload` 包含某个 Tile 的节点内容；不是整份地图 style 配置。（G9） |
| MVT / MBTiles / style.json | 矢量 Tile 格式／SQLite Tile 容器／样式配置 | 三者处于不同层面；MBTiles 可能存栅格或矢量，style.json 不是 Tile 数据文件。（G6、G9、G12） |
| Handle / Ownership / Lifetime | 句柄／所有权／生命周期 | 复制 Handle 不必然转移 Ownership；Source、外部 OGR Layer、游标与 VSGContext 均需核对所有者。（G2、G12） |
| Iterator / Cursor / Chunk | 迭代器／读取游标／分块 | 逐批产生 Feature，不表示全部数据已被渲染，也不限制调用方最终收集的总量；对象的 Lifetime 需核对。（G12） |
| Thread-Local / Read Lock / Write Lock | 线程局部／读锁／写锁 | SRS/GDAL 有线程局部资源；Registry 的读写规则不表示全部场景都可任意并发修改。（G6、G7、G10） |

## 渲染基础库与 I/O 补充

| 英文原名／代码标识 | 中文释义 | 在本轮来源中的含义与边界 |
| --- | --- | --- |
| Object / ref_ptr | 基础对象／引用计数指针 | VSG Object 支持引用计数、遍历和元数据；ref_ptr 管 Lifetime，不自动保护任意并发写或 GPU 资源退休。（F1） |
| Visitor / accept / traverse | 访问者／分派／遍历 | accept 选择对应 apply，traverse 访问内容；不同 Visitor 的执行语义不同，不保证都访问全部 Child。（F1） |
| StateGroup / StateCommand | 状态作用组／状态命令 | VSG RecordTraversal 进入/退出 StateGroup 时维护状态栈；不是 OSG StateSet 的兼容替代类。（F1） |
| StateSet（OSG） | 场景关联的渲染状态集合 | OSG 的状态表达对象；完整继承及 Draw 应用规则留后续分析，不套用 VSG 的 Record 机制。（F7） |
| CommandGraph | 命令记录组织 | VSG 对 Device/Queue、CommandBuffer 的组织，可关联 Window；不等于 Scene Graph 的空间层级。（F2） |
| RenderGraph | Render Pass 组织 | VSG 中配置 Framebuffer/Window、区域与 Clear Values 等；不能仅凭名称推断具有通用 Frame Graph 的自动依赖调度。（F2） |
| Render Pass / Framebuffer | 渲染过程配置／附件绑定目标 | 属于 Vulkan 渲染资源与输出组织；不是地图 Layer 或文件数据集。（F2） |
| Record / Submit / Present | 记录命令／提交任务／显示结果 | 三个阶段有不同职责；CPU 完成 Record 不表示 GPU 已执行完毕。（F2） |
| CompileTraversal / CompileManager | 资源准备遍历／资源准备管理器 | VSG 运行时准备设备资源及收集结果；与 C++ Build、Shader Compiler 区分。（F3） |
| ResourceRequirements / CompileResult | 资源需求／资源准备结果 | Compile 阶段收集与传播的上下文信息；非空 Node 或文件已读不代替 Compile 成功。（F3） |
| Transfer / DataVariance | 数据传输／数据变化分类 | Data 的静态/动态属性影响 CPU→GPU 路线；dirty 增加修改计数，不能单独代替传输与更新配置。（F3） |
| ImageView / Sampler | 图像资源视图／采样配置 | VSG/Vulkan 的资源对象，与 Camera View、rocky::Image::viewAs 不是同一接口。（F3） |
| ShaderSet | Shader 及输入/绑定的配置集合 | VSG 上层配置设施；不等同于单个 Shader，也不证明所有模型材质扩展兼容。（F3） |
| ReaderWriter / CompositeReaderWriter | 数据读取写入接口／组合读取写入接口 | 组合接口按顺序尝试，首个非空 Object 即返回；调用 read 不保证同时具备 write。（F4） |
| ObjectFactory / Type Registration | 对象工厂／类型登记 | 登记可创建或反序列化的类型；与把 Reader 实例放入 Options 参与实际读取不同。（F4） |
| Options / extensionHint | 读取上下文／格式提示 | 包含 Reader、路径、共享等；流/内存通常需 Hint，不能靠字节来源自动恢复相对目录。（F4） |
| SharedObjects | 共享对象管理 | 用于对象复用/重复加载协调；不是磁盘 File Cache，也不是 Pager 的 Residency 管理。（F4） |
| Up Axis / Z_UP / Y_UP | 向上轴／Z 轴向上／Y 轴向上 | 局部坐标约定；不代替 SRS、EPSG、单位或地理定位。（F4、F5） |
| PagedLOD | 按需读取细节子图的节点 | 本版 VSG 具有高/低细节两个 Child；RecordTraversal 按阈值选择，不能套用到任意 OSG PagedLOD 结构。（F6） |
| DatabasePager | 外部子图请求与合并调度器 | 本版 VSG 执行后台 Read/Compile 及 Update Merge；与 Rocky TerrainTilePager、NodePager 分开。（F6） |
| Pending / MergeRequest | 待合并内容／合并请求状态 | 已读/已准备内容尚需在更新阶段挂接；存在 pending 不等于当前画面已显示。（F6） |
| glTF / GLB | 三维场景格式／其二进制封装 | 当前 vsgXchange 有原生 Reader；GLB 版本/Chunk、URI、Required Extension 仍影响兼容。（F5） |
| Primitive / Accessor / BufferView | 几何基本单元／类型化数据访问描述／缓冲区视图 | glTF 中连接 Mesh 与原始 Buffer 的不同对象；不是简单按一个 Buffer 对应一个 Draw。（F5） |
| Tileset / Tile content | 三维 Tile 集合／单个 Tile 的内容引用 | vsgXchange Tiles3D 将层级描述转换成 Node；content URI 指向的内容仍需相应 Reader。（F5） |
| Geometric Error / Screen Height Ratio / SSE | 几何误差／屏幕高度占比／屏幕空间误差 | 当前 Builder 把误差转换为 VSG 阈值；pixel_ratio 不是与 Cesium 像素 SSE 一一对应的参数。（F5、F6） |
| ADD / REPLACE | 累加／替换的 Refine 语义 | 是 3D Tiles 的策略值；当前 Builder 的 ADD 可由外层 Group 保留 local content，不直接等同于 Rocky RefinePolicy 枚举。（F5） |
| Feature Table / Batch Table / RTC_CENTER | 实例/内容描述表／批次属性表／相对中心参数 | B3DM 等内容读取涉及的结构；解析它们不自动产生完整 Feature Picking、属性编辑或旧 Payload 兼容。（F5） |
| Map / Layer / Earth File（osgEarth） | 地图模型／配置单元／地图配置文件 | 本轮只按官方文档理解组合关系；不当作 Rocky 配置格式或固定源码实现结论。（F8） |

## 容易混淆的用词示例

| 应使用的表达 | 说明 |
| --- | --- |
| 配置数据源的 `Profile`；按 Profile 请求 Tile | Profile 是对象，Tiling 是机制；不把所有与 Tile 相关的工作统称为一个中文动作。 |
| TerrainTilePager 执行 Paging，TerrainTileNode 判断 Refinement | 调入数据与选择细节有关联，但不是同一步。 |
| FeatureBuilder 做线段 Subdivision，面数据按相应路径 Triangulation | 产生曲面采样点与生成三角形不能混为一个算法。 |
| 用 GeoExtent 表示数据范围，用 Bounding Volume 判断场景可见性 | 两者都可能影响请求，但类型、坐标表达和职责不同。 |
| 对 GeoImage 做 Crop；对 Node 做 Culling；用 CLIP 选项控制 MVT Clipping | 同一个中文译词不能代替三种行为。 |
| CPU 解码 Terrain-RGB，内部编码为 R16，Vertex Shader 还原高度 | 输入格式、内部存储与 GPU 消费是三个阶段。 |
| C++ 编译构建程序；运行时 Compile 准备 VSG 资源 | “编译成功”必须明确是在说哪个阶段。 |
| 注册 Reader 类型；把 Reader 实例加入 Options；read 后再 Compile | 类型登记、I/O 选择和设备资源准备是三件事。 |
| 由 vsgXchange Builder 构造 PagedLOD，由 VSG DatabasePager 完成 Paging | 文件解析和运行时调度分属不同对象；不能把内部 children.tiles 当作缺失文件。 |
| 查看 PNTS 的实际 read_pnts 实现，再判断可用性 | 声明扩展名与 getFeatures 返回能力标志，均不能替代实现检查。 |
