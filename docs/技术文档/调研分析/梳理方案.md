# 渲染基础库架构梳理方案

方案版本：v1。用户在四库架构调研方案后要求“开始实现”，本轮执行全部 P0。主任务为 [rocky／技术文档-002](../任务/002-渲染基础库架构调研.md)，不与已有 Rocky 架构梳理任务混记。

## 目标与分析方法

读者应能说明：谁负责 GIS，谁负责 Scene Graph，谁把文件变成 Node，谁准备 GPU 资源，谁执行 Paging，以及现成接口与需要新研发的边界。优先追踪能帮助 GeoStudio 使用已有能力的调用链，不因调研转入 Renderer 重写、格式补丁或宿主改造。

每条核心链按“公开入口 → 数据对象 → 内部实现 → 调用者 → 资源与线程阶段 → 错误/缺口”展开；列出固定版本、稳定符号和本地源码入口。中文负责解释，底层机制、类和字段使用[英文术语](../术语.md)。

## 证据、验证与关卡

源码观察、官方说明、设计建议、既有构建配置、项目运行结果分开标识。当前使用本地锁定 VSG/vsgXchange/OSG 源码；osgEarth 仅使用官方文档，P1 必须先固定其源码版本。

本轮核对文档 UTF-8、结构、链接与 Anchor、无具体日历日期、核心符号、引用文件身份及修改边界。核对既有 CMakeCache 只能说明配置状态，不视为新构建、当前 DLL 或 GPU 验收。Markdown 中的 C++ 片段只解释调用顺序，未编译运行。

AI 自检后阶段设为待人工验收，用户确认对应本轮内容身份。源码级结论已在各章登记；暂不复制成知识库条目，以免重复未验收工程结论。P1/P2、功能修复及独立兼容测试需另行明确范围。
