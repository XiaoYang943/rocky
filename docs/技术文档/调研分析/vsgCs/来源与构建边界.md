## 本轮源码取得方式

先以 `git ls-remote` 读取 vsgCs HEAD，再通过 GitHub API 获取固定 Commit 的 Tree；逐个读取明确列出的 raw 文本文件。每个快照计算 SHA-256，并计算 Git Blob SHA-1，与固定 Tree 的 Blob ID 核对。Cesium Native 的选定依赖实现采用相同方式核对。

快照只放在工作区 [.docs-tmp/vsgcs-architecture-r1](../../../../../../.docs-tmp/vsgcs-architecture-r1)，用于文档分析和追溯，不是受 Demo 消费的 Git Checkout。取得选定文件不等于完整克隆、所有子模块、整个依赖图或全部文件都已审计。Port 中的 Archive SHA-512 仅作为上游声明，本轮未重新下载归档并核验它。

| 报告 | 内容 |
| --- | --- |
| `baseline.json` | workspace/Rocky HEAD、跟踪文件 Hash、20 份原技术文档的内容身份及保护项 |
| `repository.json`、`tree.json` | GitHub 仓库元数据和 vsgCs 固定 Tree；正文不依赖其中易变化的活跃度数字 |
| `source-identities.json` | 选定 vsgCs 文件的 URL、Commit、Blob 与 SHA-256 |
| `cesium-native-commit.json`、`cesium-native-tree.json` | 依赖 Tag 解析结果与对应 Tree |
| `cesium-native-source-identities.json` | 选定 Native 实现的身份与范围 |
| `knowledge-review.json` | 检索、阅读位置、来源状态及不采用为实现证据的理由 |
| `symbol-checks.json` | 39 项核心符号/文本一致性检查，辅助人工源码分析 |
| `verification.json` | 最终文档身份、链接、符号、修改边界和未执行项 |

这是只读源码调研；源码快照没有应用补丁、执行脚本或改变上游 Commit。旧任务 002 的报告仍只对应其原内容，本轮新增/修改的文档采用任务 003 的独立检查结果。

## 构建依赖与实际要求

| 项目 | 固定源码声明 | 对 GeoStudio 的含义 |
| --- | --- | --- |
| C++ / CMake | C++20；CMake 至少 3.22 | 不能直接复制 Rocky 的 C++17 构建假设；各 Target 的语言/工具链与 ABI 组合需核对 |
| VSG | 至少 1.1.11 | 版本下限满足只证明配置条件之一 |
| Cesium Native | 默认通过 Overlay Port 使用 0.58.0；也可指定源码目录 | 本篇兼容结论不推广到任意最新版 Native |
| ImGui / vsgImGui | 顶层 `find_package` 必需；vsgCs Target 公开链接 vsgImGui | 不要求 Qt，但构建并未完全移除 UI 依赖 |
| PROJ | `VSGCS_USE_PROJ=ON` 为默认，可关闭对应路线 | 影响 CRS 转换与数据资源，不把 PROJ 缺失解释为所有模型都无法绘制 |
| I/O 与其他依赖 | CURL、OpenSSL、spdlog、Microsoft.GSL、tinyxml2 等 | 需匹配架构、编译配置、运行资源和 DLL/静态运行库组合 |
| vsgXchange | 顶层使用可选 `find_package`，Manifest 列为依赖，上游应用有条件注册 | 区分核心 Tileset 解析与普通模型输入，不假定其全部 Importer 都可用 |
| 应用目标 | `src/CMakeLists.txt` 直接包含 vsgCs、CsApp、applications | 不虚构一个已存在的“关闭全部 UI”开关 |

以上依据 C1。当前 Native Port 的 `config.patch` 文件存在，但 portfile 没有声明应用该补丁，不能将目录中有补丁等同于本构建已应用。

`VSGCS_CESIUM_NATIVE_DIRECTORY` 允许使用外部 Native 源码；对应 `local-cesium-native` Preset 用 vcpkg 取得依赖。这是上游提供的开发路线，不是允许随意更换 Native Commit 后继续沿用旧兼容结论。

## Windows 构建入口如何读

上游 Preset 提供 `Windows-Devel`，使用 Visual Studio 17 2022 和 `x64-windows-static-md`，并提供 `Windows-Debug`、`Windows-Release` Build Preset。它们以 `VCPKG_ROOT` 指向的工具链解析依赖。[C1]

未来独立验证时，在取得完整且固定的上游源码、准备工具链并明确全新 Build/Install 输出后，可参考：

```powershell
cmake --preset Windows-Devel
cmake --build --preset Windows-Release
```

这两条是上游 Preset 对应的参考命令，本轮没有执行；不表示当前源码快照目录可直接完整构建，也不承诺已有 GeoStudio 环境已经满足前提。`vsgCs`/`worldviewer` 的实际输出和安装资源路径要按真实配置记录，不能用别的 Cache 结果代替。

正式功能验证还需检查 Shader、图像、PROJ 数据和运行库位置。Runtime Options 支持 `VSG_FILE_PATH` 并追加其编译时数据目录；这些是资源查找入口，不是输入原始 GIS 数据的索引。[C2]

## 验证边界与后续复核

知识检索中 `vsgCs` 无命中，`Cesium Native` 的两条命中为尚未治理原文，其中一个只是名称相关的规范前置内容，另一个讨论 OSGB/Cesium 背景；均不作为本库实现证据。本轮采用固定源码和直接调用点。

文档自检核对结构、链接、英文术语、版本/符号、来源 Hash 与修改范围；不运行全库测试来替代实际集成。后续升级 Native、VSG、vsgCs，或移除 ImGui/更换宿主时，应重查 Runtime、Preparer、ViewState、Shader、URI 和释放链。详细结果与待人工验收状态见[主任务 003](../../任务/003-vsgCs架构与数据链路调研.md)。
