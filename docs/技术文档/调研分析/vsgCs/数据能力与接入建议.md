# vsgCs 数据能力与 GeoStudio 接入建议

本篇依据与[架构正文](README.md)相同的固定源码，区分明确实现、可复用入口和后续研发。所有用例均为建议，未在本轮构建、启动或验收。C/N 编号见[源码证据](来源与构建边界.md#源码证据)。

## 六大类原始数据与预处理数据

| 业务分类 | 具体输入 | vsgCs 当前明确路线 | 建议与边界 |
| --- | --- | --- | --- |
| 矢量 | SHP、GeoJSON、GPKG 等原始 Feature | 没有在本轮核心链中找到对应 GIS FeatureSource | 沿用 Rocky GDALFeatureSource、FeatureBuilder、ECS；不因 glTF 支持 Line/Point 就认为能解释矢量文件及 SRS |
| 栅格 | 带地理信息的影像 TIFF | 图像/纹理解码不提供 GeoTIFF 地理 Layer 的完整流程 | 沿用 Rocky GDALImageLayer；勿把纹理加载当作地理影像验收 |
| 三维地形 | 高程 TIFF、DEM | 未见直接 DEM→Terrain 的 vsgCs 入口 | 沿用 Rocky GDALElevationLayer；不在当前调研中新增地形转换器 |
| 三维地形 | Quantized Mesh `layer.json` 与 Terrain Tile | Cesium Native 检测 Terrain 格式并加载、转换为渲染内容 | 有明确现成路线，可优先验证；不是直接打开孤立 `.terrain` 文件 [N3] |
| 三维模型 | glTF/GLB | GltfLoader、CesiumGltfReader、ModelBuilder | 可验证模型、纹理、坐标和实例；当前 Native GLB 路线只接受版本 2 [C5、C11、N2] |
| 三维模型 | OBJ 等 | 上游示例允许接 vsgXchange；实际受 Reader 顺序、Assimp 构建及定位影响 | 已有 Demo 的 OBJ 路线优先保留，不把它重新包装成 vsgCs 独有能力 [C10–C11] |
| 倾斜摄影 | 组织为 3D Tiles 的 B3DM/CMPT/I3DM/glTF 等 | Cesium Native 内容转换 + vsgCs Renderer Adapter | 值得优先验证；倾斜摄影是业务来源，具体 Payload 仍决定兼容 [C3–C5、N1] |
| 倾斜摄影 | OSGB 原件 | 当前 vsgCs 核心链未见直接 OSGB Reader | 不将已有 3D Tiles 读取通过记成 OSGB 原件通过；转换路线另议 |
| 点云 | Tileset 引用 PNTS | PntsToGltfConverter → glTF Points → VSG Point Pipeline | 有明确现成实现，优先于自写 PNTS Reader；用 Tileset 验证，不把裸 PNTS 当作通用顶层模型 [C5–C6、N1] |
| 点云 | LAS、LAZ、COPC 原件 | 本轮未找到直接原始点云读取链 | 另行确认专用库/转换或原生渲染接口，降低本轮接入优先级 |

“本轮未见入口”限定于被检查的 vsgCs 核心模块，不能作为所有 Cesium Native 版本、第三方插件或 VSG 生态都不支持的证明。已有 Rocky 数据路线参见[栅格](../../栅格/README.md)、[三维地形](../../三维地形/README.md)、[矢量](../../矢量/README.md)。

## Tile 数据分别如何输入

| 数据 | 推荐输入 | 现成路线与注意点 |
| --- | --- | --- |
| 3D Tiles | `tilesetUrl` 指向 Tileset JSON，或 ion Asset ID | Native Tileset 负责 Tile Selection 和子内容加载；不是 vsgXchange 的虚拟 `children.tiles` 路线 |
| Cesium Quantized Mesh | `tilesetUrl` 显式指向 `layer.json` | Native 要识别 `format=quantized-mesh-1.0`；继续检查模板、可用范围、投影、相对路径与扩展 |
| 栅格 XYZ | UrlTemplateRasterOverlay 的 `url`、Level、尺寸和投影 | URL Template 中 y/reverseY 的约定要与源数据一致；作为影像附于 Tileset |
| TMS | TileMapServiceRasterOverlay | 读取 TMS 服务描述/Tile 路线；不是任意 z/x/y 文件夹都自动得到正确布局 |
| WMS / WMTS | 对应 Overlay 类型与服务参数 | 已有包装；JSON 配置暴露的参数不一定覆盖 C++ 类全部字段 [C7] |
| Terrain-RGB / Mapbox RGB Terrain | 不按普通 Overlay 验收高程 | 将 RGB 当影像只得到颜色；继续用已验证的 Rocky RGB 高程路线 |
| MVT / MBTiles / MapLibre style.json | 不通过本篇 World JSON 代替 GIS 路线 | 当前 vsgCs 的 Raster Overlay 与 Styling 不等于 MVT Reader、SQLite 容器服务或 MapLibre 样式引擎 |

影像 Overlay 需要可承载的地形/其他 Tileset 表面。本轮没有建立无地形的独立二维地图模式，也没有把 Cesium Native 的所有 Raster Overlay 类型等同于已被 vsgCs 包装。

## 本地 URL、ion 与 Windows 路径

URL 路线不要求 ion 账户或 Token。默认 Accessor 基于 libcurl，Native Loader 对状态码 0 的成功响应有明确接受分支，和本地文件传输相容；当前源码有本地文件入口。Windows 上建议显式构造 `file:///D:/...` URI，并核对路径编码与 JSON 转义，实际可用仍须功能验证。[C2–C3、C10–C11、N3–N4]

上游 worldviewer 对直接文件参数使用 `"file://" + absPath.string()`，然后拼入 JSON。该路径构造对 Windows 反斜线、空格及特殊字符需要专门复核；不能据此宣称任意资源管理器返回的路径都已正确处理。作为隔离用例，可先使用显式 World JSON 和规范 File URI；需要排除传输差异时再使用已有的本地 HTTP 服务，不在本轮新建服务。

推荐 World 配置示意如下，路径均为示例，两个数据源互不证明对方已可用：

```json
{
  "Type": "World",
  "tilesets": [
    {
      "Type": "Tileset",
      "tilesetUrl": "file:///D:/data/example-terrain/layer.json"
    },
    {
      "Type": "Tileset",
      "tilesetUrl": "file:///D:/data/example-3dtiles/tileset.json"
    }
  ]
}
```

显式 `tilesetUrl` 对 Terrain 尤其有用：worldviewer 对普通 JSON 文件名的自动识别主要检查 Tileset `asset.version`，不应假设它会把任意本地 `layer.json` 参数自动识别成 Terrain。URI 及配置入口的核对优先于添加新的格式解析代码。[C8、C10、N3]

## 两条 3D Tiles 路线如何选择

| 比较项 | vsgXchange 当前锁定路线 | vsgCs 本轮分析路线 |
| --- | --- | --- |
| 输入解释 | Tiles3D Reader 与 Builder | Cesium Native Tileset/Converter |
| 调度 | PagedLOD + VSG DatabasePager | Cesium Native ViewUpdateResult 与 loadTiles |
| VSG 接口 | Reader 返回 Node，运行时 Paging/Compile | IPrepareRendererResources 与每帧 TilesetNode Update |
| PNTS | 已读固定源码的 `read_pnts` 未实现 | 0.58.0 Native Converter 与 vsgCs Point Pipeline 有明确实现 |
| Quantized Mesh | 原调研未给出该 Reader 的 Terrain 专用路线 | Native `layer.json` Loader 是明确路线 |
| 旧 Payload | 需要按 Header/GLB 布局核对 | B3DM 有 Legacy Header 分支；GLB 1 仍被当前 GltfReader 拒绝 |
| 接入成本 | 当前 Demo 已有依赖与相关加载入口 | 新增 Cesium Native、vsgCs 及其运行/构建组合，需要独立验证 |

现有 vsgXchange 结论见其[架构正文](../vsgXchange/README.md)。这里比较的是两组明确来源，不能把“Native 路线更完整”推广为所有数据兼容、质量或性能都必然更好。建议后端按数据路线明确选择，避免两个调度器重复管理同一 Tileset。

## GeoStudio 的接入分层建议

先保留现有数据与渲染职责：Rocky 负责原始 GIS，vsgXchange 负责已有普通模型读取，vsgCs 候选负责 Cesium Native Tileset/Terrain/PNTS。应用层统一数据源状态、显示控制与错误反馈；来源接口和渲染后端分开，便于后续分别构建 Web/Desktop。

共享 VSG 不代表零接入工作。至少需要明确：

1. **Device/Viewer**：谁创建 Device；vsgCs 所需 Feature、格式和 Shader 资源是否在创建前准备。不能额外启动第二套 Viewer 来冒充同一场景已经集成。
2. **Camera/View**：Tileset 的 Update Operation、View 注册和 ECEF/Up Axis 约定与宿主一致。自定义 Graph 层级、父 Transform、多窗口应有单独用例。
3. **Shader/Descriptor**：vsgCs 的 World/View/Tile 状态与 Rocky 场景作用范围要明确，不能假定所有 PBR Shader 的绑定布局相同。
4. **异步和释放**：保持 Main Thread Dispatch、Compile、Update、关闭和重载顺序；本轮未证明任意停帧/关窗场景都能正确收尾。
5. **资源身份**：固定完整依赖组合，确认数据/Shader/PROJ 资源路径；不混用两套安装目录中的同名 VSG DLL。

这是后续实施设计，不是本轮已集成的行为。现有 Rocky NodeLayer 可承载 VSG Node 这一事实，也不能替代上述步骤。

## UI：Qt 与 React

没有必须使用 Qt 的要求。上游 worldviewer 的 UI 是 ImGui/vsgImGui；当前 CMake 配置强制查找这些依赖，vsgCs 库本身公开链接 vsgImGui，不能把“不要求 Qt”理解为“核心构建已完全不带 UI 依赖”。[C1、C10]

React 可继续负责应用界面，通过原生宿主接口控制 C++ 数据/场景；Vulkan 画面仍需要原生 Surface、事件和生命周期。该库没有现成 React Component。若以后移除上游 ImGui 依赖，需要单独评估构建和 Credits 展示的连接；本轮没有更换 GeoStudio UI 或复制 worldviewer 到 Demo。

## 建议验证优先级

以下是后续功能验证建议，不与四库调研原方案的 P0/P1 混记，也不代表已批准开始改代码。

| 优先级 | 验证项 | 为什么先做 | 最小通过条件 |
| --- | --- | --- | --- |
| P0-A | 独立固定版本的 vsgCs/worldviewer 构建与本地入口 | 先确认工具链、依赖组合、Shader/数据路径和 File URI | 能启动、打开小型已知有效数据，日志与实际加载来源清楚 |
| P0-B | 小型 B3DM/GLB 2 3D Tiles | 现成转换、调度、渲染链完整 | 子 Tile、纹理、Bounds/位置和视角变化正常；不以 Node 非空代替画面 |
| P0-C | 小型 Quantized Mesh Terrain | 弥补明确 Terrain 协议方向 | layer.json、多个层级、地形形状和影像附着可验证 |
| P0-D | 小型 PNTS Tileset | 已有 Converter 与 Point Pipeline，优先于新 Reader 研发 | 点位置、颜色、点大小与多个层级正确；不记为 LAS/LAZ 原件通过 |
| P1-A | DNHDL 特定 3D Tiles 1.0 的兼容定位 | 先区分传输、Header、GLB 版本、扩展和变换 | 定位实际失败阶段；遇到 GLB 1 等缺口时单列转换/补丁工作，不自动扩展研发 |
| P1-B | 复用 Rocky Viewer、既有 React 宿主 | 需处理 Device、View、Shader、异步与释放 | 同场景正确显示、交互、移除与重载；无重复调度 |
| P2 | 原始 OSGB/LAS/LAZ、新格式 Reader、完整样式/编辑 | 不属于本库当前已确认的直接路线 | 另行选择方案与授权，不阻塞现成接口验证 |

不在本轮追加大体量性能门槛。Native 的实现形态不能单独证明同一原始数据必然优于 CesiumJS；当前先验证正确性与接口链路即可。

## 未执行与恢复入口

本轮没有获取 SDK 安装副本、配置 CMake、编译、启动 worldviewer、使用 ion Token、访问实际服务或读取 DNHDL 数据。源码测试和示例存在不等于本机运行通过。构建路线与版本差异见[来源与构建边界](来源与构建边界.md)，实施授权和自检见[主任务 003](../../任务/003-vsgCs架构与数据链路调研.md)。
